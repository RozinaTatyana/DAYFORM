# DAYFORM

DAYFORM — универсальный личный организатор с пятью страницами: обзор, план дня, проекты, привычки и аналитика. Есть отдельный заполненный демопример и раздел «Мои данные»; они хранятся раздельно в браузере. Кнопка «Сбросить пример» возвращает текущий раздел к исходному состоянию.

Персональный дашборд на чистом JavaScript: задачи, фокус-сессии, график за семь дней, привычки, заметки, мысли дня, погода и качество воздуха. Дизайн вдохновлён предоставленными референсами: светлая асимметричная сетка, нейтральные поверхности, лаймовый акцент.

## Запуск

### Windows: в один клик

После распаковки архива дважды нажмите `DAYFORM.html` в корне папки. Это автономная версия: ей не нужны Node.js и окно терминала. Не открывайте `dist/index.html` двойным кликом: это исходная модульная версия для разработки.

`start-dayform.cmd` оставлен для разработки через локальный сервер и требует установленный Node.js.

Нужен Node.js 20 или новее. Зависимостей нет.

```sh
npm start
```

Откройте http://127.0.0.1:4173. Порт 4173 должен быть свободен. Не открывайте `dist/index.html` через `file://`: ES6-модулям нужен HTTP-сервер. Для другого статического хостинга загрузите содержимое `dist/`.

```sh
npm run check
node verify-behavior.mjs
```

## Архитектура и ООП

- `dist/index.html`: доступная структура страницы, каталог виджетов в нативном dialog.
- `dist/main.js`: инициализация и регистрация типов, общие действия страницы.
- `dist/js/UIComponent.js`: абстрактный базовый класс с конфигурацией, `render()`, `minimize()`, `close()`, `serialize()` и `destroy()`. Создавать его напрямую нельзя. Все события привязаны к сигналу жизненного цикла.
- `dist/js/Dashboard.js`: приватные коллекции экземпляров и регистраций; `addWidget(widgetType)`, `removeWidget(widgetId)`, перемещение, сохранение, история сессий. Новый тип добавляется через `register()`, без изменения фабрики Dashboard.
- `ToDoWidget`: приватный массив задач и делегирование событий; добавление, удаление и отметка выполненных задач.
- `FocusWidget`: таймер на 15/25/45 минут, пауза, сброс; считает оставшееся время по абсолютному времени, а не количеству срабатываний интервала. Записывает завершённую сессию.
- `RhythmWidget`: отображает реальные завершённые сессии за семь дней. Пустая история не заменяется выдуманными данными.
- `APIWidget`: общий сетевой жизненный цикл. `WeatherWidget` и `AirWidget` полиморфно задают URL, проверку данных и отображение.
- `HabitWidget`, `NoteWidget`, `QuoteWidget`: независимые состояния ритуалов, заметок и мыслей. Тексты мыслей — оригинальные заметки DAYFORM, а не приписанные известным людям цитаты.
- `storage.js`: безопасное чтение и запись локального состояния, ключи календарных дней.
- `styles/main.css`, `styles/components.css`: общая адаптивная сетка и оформление компонентов.
- `serve.mjs`: минимальный локальный сервер. `verify.mjs` и `verify-behavior.mjs`: проверка синтаксиса, ресурсов и важных сценариев.

Наследование обеспечивает общий контракт; инкапсуляция закрывает коллекции; полиморфизм позволяет Dashboard работать с разными экземплярами через общий интерфейс. Классы отвечают за свои виджеты; Dashboard отвечает за композицию.

## Источники данных

Два API-виджета обращаются к разным API Open-Meteo без секретных ключей:

1. Погода: https://open-meteo.com/en/docs — текущая температура, ощущаемая температура, код погоды.
2. Воздух: https://open-meteo.com/en/docs/air-quality-api — европейский AQI, данные CAMS.

Города: Москва, Петербург, Казань, Сочи, Калининград. Город выбирается отдельно для каждого виджета; точная геолокация пользователя не запрашивается. Подпись Open-Meteo / CAMS находится внизу панели. Данные провайдера распространяются по CC BY 4.0; ограничения бесплатного API смотрите в документации провайдера.

Каждый API-виджет имеет загрузку, успешный результат, пустой результат и ошибку. Новый запрос отменяет предыдущий через AbortController. Ответ дополнительно проверяется на актуальность экземпляра запроса. Через 12 секунд показывается ошибка ожидания. При удалении прекращаются запросы и таймеры. Внешние данные и пользовательский ввод отображаются через `textContent`, без `innerHTML`.

## Управление и доступность

Добавление через каталог; удаление и сворачивание в заголовке карточки. Кнопка «Расположение» показывает «Раньше» / «Позже» для каждого виджета; перетаскивание не требуется. Все действия доступны клавиатурой, фокус видим, нативный dialog поддерживает Escape. Таймер не озвучивается каждую секунду; завершение объявляется через live region. Учитываются настройки уменьшения движения. Один виджет не меняет состояние другого; графики имеют текстовое описание.

В поддерживаемых браузерах регистрируется необязательный WebMCP-инструмент добавления задачи. Он вызывает тот же метод, что и форма. В обычных браузерах этот блок пропускается.

## Хранение и ограничения

Состояние локально для браузера и адреса сайта, без серверной синхронизации. Не храните чувствительные данные. Очистка данных сайта удаляет сохранённые задачи и историю. При закрытии или перезагрузке страницы таймер восстанавливается на паузе; закрытый сайт не продолжает сессии в фоне. Привычки отмечаются по локальной календарной дате браузера. Дневная история ограничена последними 2000 сессиями, панель — 32 виджетами, список задач — 200 элементами, ритуалы — 12 элементами. Ритуалы можно добавлять и отмечать; отдельного удаления ритуала нет, можно удалить его виджет.

Для API необходим интернет. Недоступность API показывает ошибку и кнопку обновления, без поддельных показателей. Погода и воздух — модельные данные, не показания персонального датчика. AQI здесь только информативный показатель. Manrope загружается из Google Fonts; при недоступности используется системный Arial.

## Проверка

Автоматически: синтаксис модулей и локальные ссылки; защита от устаревшего ответа; пустой ответ; ошибка API; отмена при уничтожении; запись завершённой фокус-сессии. Браузерные проверки: задачи и их выполнение, добавление независимого экземпляра, удаление и сворачивание, запуск/пауза/сброс таймера, перемещение и восстановление после перезагрузки; реальные ответы обоих API; узкий и широкий экран. WebMCP проверен валидным и невалидным вводом. Не проводились длительное нагрузочное тестирование и полный аудит WCAG.

## Публикация и сдача

Проект подготовлен для статического хостинга; `.openai/hosting.json` задаёт каталог `dist`. Версия в Sites первоначально приватная для владельца. Перед отправкой преподавателю обеспечьте доступ к сайту и репозиторию. Исходники находятся в Git-репозитории проекта; для GitHub добавьте свой remote и отправьте коммит. Не публикуйте временные credentials. Формат сдачи: ФИО, доступная преподавателю ссылка на сайт, ссылка на доступный Git-репозиторий.
